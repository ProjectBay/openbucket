# i18n convention — no hardcoded UI strings

EPIC-07 (STORY-0617). The admin console ships English (`en`) and German (`de`) via
ngx-translate. Every user-facing string in a feature **template** must go through a
translation key — never a hardcoded literal.

## Rules

1. **Template strings use keys.** Wrap visible text with the `translate` pipe and
   add the key to **both** `apps/openbucket-frontend/src/app/i18n/en.translations.ts`
   and `de.translations.ts`:

   ```html
   <h3 hlmCardTitle>{{ 'buckets.title' | translate }}</h3>
   <button hlmBtn>{{ 'buckets.create' | translate }}</button>
   ```

   Bind attribute labels the same way: `[attr.aria-label]="'keys.delete' | translate"`.

2. **Page header / action button.** `PageHeaderService.setPageHeader(...)` and
   `setActionButton(...)` take translation **keys** (the header pipes them through
   `translate`), e.g. `setPageHeader('buckets.title')`.

3. **Keys are namespaced per screen.** Top-level groups: `sidebar`, `breadcrumb`,
   `notFound`, `settings`, `auth`, `dashboard`, `command`, `keys`, `bucketDetail`,
   `share`, `buckets`, `objects`. Keep `en` and `de` structurally identical.

4. **Data values are not translated.** Bucket names, object keys, access-key IDs,
   ETags, etc. render verbatim.

5. **Toasts / errors (TS).** Strings created in TypeScript (`notify.*`, `messageFor`)
   are not template literals; where they should localize, resolve via
   `TranslateService.instant('key')` before display. Transient toasts may stay
   English in v1 — prefer keys for new ones.

6. **Prune dead keys.** Remove keys for routes/pages that no longer exist (e.g. the
   old `sidebar.workspace` / `sidebar.content` groups were pruned in STORY-0617).

## Check

`grep` for hardcoded literals in feature templates as a smoke test, e.g.:

```bash
# Flags text nodes inside templates that aren't interpolations/keys (heuristic).
grep -rnE '>[A-Z][a-z]+ ' apps/openbucket-frontend/src/app/<feature> --include=*.ts
```

An optional angular-eslint rule (`@angular-eslint/template/i18n`) can enforce this in
CI; it is not enabled yet to avoid noise on data-bound and attribute text.
