## Goal
Verify the three highWaterMark sites use the shared constant `256 * 1024` and that a 1 GiB PUT keeps process RSS under 256 MiB.

## Setup
- Read the three handler files as text.
- For the memory probe: a supertest harness that PUTs a 1 GiB body generated by a `Readable` emitting 256 KiB chunks. Only runs when `OPENBUCKET_MEMPROBE=1`.

## Cases
1. Grep `STREAM_HIGH_WATER_MARK_BYTES` import in `put-object.interceptor.ts`, `get-object.handler.ts`, `upload-part.handler.ts`.
2. Assert `STREAM_HIGH_WATER_MARK_BYTES === 256 * 1024`.
3. README at `apps/backend/src/s3/object/README.md` contains all three "never" rules verbatim.
4. (opt-in) PUT 1 GiB; sample `process.memoryUsage().rss` every ~50 chunks; assert peak RSS < 256 MiB.

## Tooling
- Framework: jest, supertest, fs
- Runner: `nx test backend --testPathPattern=backpressure.spec.ts`

## Pass criteria
- [ ] Cases 1–3 always pass.
- [ ] Case 4 passes when `OPENBUCKET_MEMPROBE=1` is set in the runner env; otherwise it is `skip`'d.
